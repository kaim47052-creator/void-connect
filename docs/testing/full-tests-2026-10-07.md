## Что проверяют тесты

15 widget tests: RU/EN и сохранение выбора, fallback языка, ширины 320/1280, добавление/поиск/запуск/удаление, недоступное приложение, Ctrl+F/Escape и обход фокуса, отключённые анимации, изменение нативного предпочтения движения через подменённый канал, крупный текст в двух языках, подписи действий, размеры целей нажатия, контраст и диалог на узком экране.

Новые 6 integration tests используют настоящий runner без подмены каналов приложения:

- Каталог приложений: непустые имена/идентификаторы, отсутствие дубликатов, Windows `.lnk`, исключение собственного Android-пакета.
- Добавление/удаление временного Unicode-идентификатора, повторные операции без дубликатов, сохранность исходных записей.
- Отклонение пустого идентификатора при добавлении, удалении и запуске.
- Ошибка неверного расширения в Windows до вызова ShellExecute; ошибка отсутствующего пакета в Android.
- Отклонение неверного языка без изменения настройки; запись RU/EN и восстановление исходного языка, когда предпочтение уже существовало.
- Чтение настоящего Windows-предпочтения движения, запуск UI, открытие и закрытие диалога с настоящим каталогом.

На телефоне Flutter создаёт новую тестовую установку, поэтому нативный тест языка проверял отсутствующее предпочтение и неверный код. Сохранение RU/EN после перезапуска отдельно подтверждено через интерфейс обычного приложения.

## Найденный и исправленный дефект

Первый нативный прогон Windows обнаружил, что `addApp('')` возвращает успех. В обработчик Windows добавлено отклонение пустого идентификатора и строки из пробелов/табуляции/переводов строк до записи или запуска. Повторный прогон подтвердил отклонение пустого идентификатора и сохранность записей.

## Android: обычная установка и сохранность данных

Перед тестами сохранены обычный debug APK и настройки библиотеки/языка. После завершения integration tests Flutter удалил тестовый пакет. Восстановлены обычный APK и исходные настройки; значения языка и набор идентификаторов сравнены с резервной копией и совпадают. Пользовательские записи не удалены.

Дополнительно через ADB/UI Automator подтверждены смена EN → RU, русский интерфейс после принудительного завершения и нового запуска, возврат EN и сохранение английского после перезапуска. Кнопка запуска существующей записи открыла соответствующее приложение: Android подтвердил целевую активность. Его содержимое не просматривалось. Затем выполнен возврат в Void Connect.

Release APK установлен поверх обычной установки; подтверждены старт английского интерфейса и наличие исходной записи библиотеки. После проверки установлен свежий обычный debug APK. Набор идентификаторов и язык повторно совпали с исходными. В выборке 57 строк журнала процесса последнего запуска нет `FATAL EXCEPTION`, `RenderFlex overflow` и `EXCEPTION CAUGHT BY`; это ограниченная выборка журнала.

Windows integration tests добавлены в GitHub Actions перед release-сборкой; форматирование проверяет новую папку. Android integration tests требуют подключённого устройства и выполнялись локально, а не в CI.

## Границы проверки

Реальная физическая клавиатура, Narrator/TalkBack и переключение системного флажка анимаций Windows остаются ручными проверками. Ограничения инструмента и предыдущие проверки на устройстве описаны в [отчёте 2026-10-06](device-smoke-2026-10-06.md). Успешные тесты не заменяют эти сценарии. Несуществующий `.lnk` с реальным вызовом ShellExecute в этом прогоне отдельно не проверялся.

Windows integration tests запускали debug runner с настоящим интерфейсом. Новая release-сборка проверена на этапе компиляции и комплектации; отдельный запуск через Windows Computer Use не подтверждён: помощник вернул `accessibility window-opened handler did not become ready`, затем список окон не содержал Void Connect.
