# ADR 0001: Каталог приложений и запуск на Windows и Android

- **Статус:** принято
- **Дата:** 2026-10-05
- **Область:** MVP библиотеки приложений

## Контекст

Библиотека должна перечислять доступные для запуска приложения, хранить выбранные пользователем элементы, уметь искать, добавлять, удалять и запускать их. Формат каталогов и возможности Windows и Android различаются; виджеты не должны зависеть от системных API. На Android также действует фильтрация видимости пакетов.

## Решение

- Функция `launcher` владеет моделью `LaunchableApp` и обращается к платформе через один MethodChannel-контракт.
- Kotlin-адаптер Android перечисляет activity с `ACTION_MAIN` и `CATEGORY_LAUNCHER`, открывает выбранный пакет через его launch intent и хранит выбранные package ID в `SharedPreferences`.
- Манифест запрашивает видимость только приложений, подходящих под launcher intent. `QUERY_ALL_PACKAGES` не добавляется.
- C++-адаптер Windows перечисляет `.lnk` ярлыки из личного и общего меню «Пуск», запускает выбранный ярлык через ShellExecute и хранит выбранные пути в `%APPDATA%/VoidConnect/app-library.txt`.
- В общей библиотеке сохраняются только системные ID, а не дубли названий. Это позволяет показывать актуальные имена и обнаруживать удалённые приложения.

## Последствия

- Оба адаптера имеют одинаковые методы: список доступных приложений, чтение/изменение выбора и запуск. Widget tests могут подменить MethodChannel.
- На Windows недоступны приложения, у которых нет ярлыка в одном из меню «Пуск». Прямой ввод произвольного пути пока не входит в MVP.
- На Android видны только приложения с launcher activity. Приложения без значка в системном лаунчере не включаются.
- Нативные файлы и ограничения необходимо отдельно проверять сборкой и ручным запуском на обеих платформах.
